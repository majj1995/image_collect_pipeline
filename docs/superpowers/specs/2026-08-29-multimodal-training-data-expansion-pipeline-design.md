# 多模态后训练图片数据扩充管线设计

日期：2026-08-29  
状态：已获用户授权，可按本规格自主实现并在最终阶段进行功能验收

## 1. 背景与目标

本项目构建一个本地单用户 Web 工具，用于为多模态大模型后训练快速扩充图片数据。首版覆盖两种任务：

1. 广告内容品类标注：识别广告宣传的主商品，并归入唯一叶子标签，例如 `电商快销 > 3C及电器 > 影音电器 > 音箱`。
2. 内容审核：允许一张图片对应多个风险标签，并对敏感素材采用更严格的预览与导出控制。

核心闭环是：批量输入细粒度标签与图像条件，聚合多个互联网图片搜索 API，人工筛选候选图，最后一键下载包含图片与可追溯元数据的 ZIP。

首版成功标准：用户可在本地创建任务、批量导入标签、从至少一个无需密钥的真实来源以及任意已配置的付费来源获得候选图、完成筛选，并下载结构正确且可校验的 ZIP。

## 2. 范围与非目标

### 2.1 首版范围

- 本地单用户运行，默认仅监听 `127.0.0.1`。
- React + TypeScript 前端和 Node.js + Fastify 后端。
- SQLite 保存结构化状态，文件系统保存缩略图、原图缓存和导出文件。
- 批量标签路径、锁定父路径后粘贴叶子、商品别名、必须包含、排除内容、图像风格与目标数量。
- Openverse、百度千帆、Brave Images、SerpApi、DataForSEO 五类适配器；未配置凭据的适配器自动禁用。
- 多源并发检索、结果归一化、来源聚合、精确去重与近重复分组。
- 人工选择、拒绝、换类、授权确认及风险覆盖。
- 严格合规与内部研发两种导出模式。
- JPEG、PNG、WebP 静态图片；导出统一安全重编码为 JPEG 或保留必要透明通道的 PNG。

### 2.2 明确非目标

- 不执行模型训练、数据上传或云端同步。
- 不提供多人协作、账号、权限或审核流转。
- 不绕过登录、付费墙、验证码、防盗链或平台反爬措施。
- 不抓取 Google/Bing/Baidu 图片搜索网页 DOM。
- 不在首版加入目标检测框、分割掩码或自动生成最终业务标签。
- 不让自动评分替代人工选择；自动检查只负责排序、警告和技术阻断。

## 3. 已确认的关键决策

- 采用本地模块化单体，而非纯前端或 Redis/Worker 分布式架构。
- 搜索来源采用可插拔多 API 聚合，不绑定单个平台。
- 同时支持广告品类单叶子标签和内容审核多标签。
- 导出采用双模式；用户已接受授权门禁和内部研发确认机制。
- 用户只进行最终功能验收，剩余架构和视觉细节由实现方在本规格边界内决定。

## 4. 总体架构

### 4.1 组件

1. **Web 客户端**：任务列表、任务创建、采集工作台、候选审核、导出和本地设置。
2. **HTTP API**：校验请求、提供任务 CRUD、候选查询、审核事件、提供方状态和 ZIP 导出。
3. **查询规划器**：将标签、商品、别名、父级消歧词、风格和排除条件转为可编辑查询变体。
4. **提供方注册表**：发现已配置的搜索适配器，暴露能力、配额状态和权利策略。
5. **采集执行器**：按类别公平调度搜索，执行限流、重试、结果归一化和局部失败隔离。
6. **素材处理器**：安全下载、MIME 魔数识别、解码、尺寸读取、缩略图、安全重编码和去重。
7. **数据仓库**：SQLite 与磁盘目录，提供事务边界和崩溃恢复。
8. **导出器**：执行预检，生成数据集目录、manifest、taxonomy、校验文件和 ZIP。

### 4.2 运行方式

- 开发模式：一个命令并行启动 Vite 与 Fastify。
- 生产模式：构建后由 Fastify 提供静态前端和 `/api/*`。
- 默认数据目录：项目下 `.data/`，可通过 `DATA_DIR` 覆盖。
- 凭据从环境变量读取；前端只获得“已配置/未配置”状态，不获得密钥值。
- 进程内有界任务队列负责采集与下载；应用重启后从 SQLite 恢复未完成任务，运行中的步骤回退到可安全重试状态。

## 5. 搜索提供方设计

### 5.1 统一适配器契约

每个提供方实现以下能力：

```text
id, displayName, configured, enabled
capabilities: imageSearch, pagination, maxResults, locale, safeSearch
rightsPolicy: open, discovery_only, contractual
search(request, context) -> normalized search hits
healthCheck() -> provider status
```

统一搜索请求包含查询文本、期望数量、地区、语言、安全搜索、宽高比和可选游标。统一结果至少包含提供方、结果排名、缩略图 URL、原图 URL、来源页 URL、标题、描述、来源域名、尺寸、发现时间、许可名称和许可 URL。

### 5.2 首批适配器

| 提供方 | 用途 | 默认权利策略 | 配置 |
| --- | --- | --- | --- |
| Openverse | 开放许可发现层和无密钥可用的真实搜索 | `open`，仍需回源核验 | 可匿名使用，可选 OAuth |
| 百度千帆图片搜索 | 中文互联网电商广告召回 | `discovery_only` | API Key |
| Brave Images | 国际图片索引 | `contractual` | Subscription Token |
| SerpApi Google Images | Google Images 聚合补充 | `discovery_only` | API Key |
| DataForSEO Google Images | 高召回与地域化补充 | `discovery_only` | Login + Password |

单个来源 401、403、429、超时或无结果只影响该来源。结果页展示每个来源的运行状态、耗时、命中数和错误摘要。

### 5.3 凭据环境变量

```text
OPENVERSE_CLIENT_ID
OPENVERSE_CLIENT_SECRET
BAIDU_QIANFAN_API_KEY
BRAVE_SEARCH_API_KEY
SERPAPI_API_KEY
DATAFORSEO_LOGIN
DATAFORSEO_PASSWORD
```

对于需要额外存储或训练合同的来源，设置页提供“已取得相应合同权利”的本地声明开关。声明只影响导出能力，不改变第三方图片本身的版权状态。

## 6. 标签、查询与调度

### 6.1 标签输入

支持：

- 每行一个完整路径，分隔符接受 `>`、`/`、制表符并统一规范为层级数组。
- 锁定父路径后批量粘贴叶子节点。
- 自动清理 Unicode 空白、检测空层级和重复路径，并给出精确到行的错误。
- 每个叶子生成稳定 `label_id`；任务启动时固化 taxonomy 快照。

每个类别可配置主商品、别名、必须出现、排除内容、风格、目标入选数量和候选数量。主商品默认等于叶子名称，批量继承值与单行覆盖值在界面上区分。

### 6.2 查询生成

广告品类任务默认生成少量透明、可编辑的查询变体：

1. `主商品 + 电商广告词`，如 `音箱 电商海报 商品主图`。
2. `主商品 + 父级消歧词 + 宣传词`。
3. `主商品 + 风格 + 必须内容`。
4. 英文补充词：`product ad / commercial poster / product hero image / packshot / promotional creative`。

默认排除词包括 `生活随拍、街拍、开箱、测评、买家秀、lifestyle、candid、unboxing、review`，用户输入的排除条件追加到查询。提供方不支持负向查询时，排除词只进入本地软检查和人工提示。

内容审核任务用风险标签与目标场景生成查询，但不自动关闭提供方安全搜索；只有任务明确允许的风险类别才可降低安全过滤。

### 6.3 公平调度

- 所有叶子先获得首轮结果，再为未达标类别追加下一轮。
- 同一提供方按其速率限制执行；不同提供方可并发。
- 达标类别默认暂停继续消耗配额。
- 搜索运行有幂等键，重试不会创建重复候选。
- 用户可暂停、继续、只重试失败来源或失败类别。

## 7. 用户界面与核心流程

### 7.1 页面

1. **任务首页**：新建、继续、复制和删除本地任务；展示任务类型、类别进度、已选数量、来源状态和最近更新时间。
2. **采集工作台**：主要工作页面，包含类别队列、候选图库和详情抽屉。
3. **导出页面/抽屉**：展示预检、授权统计、冲突和 ZIP 生成进度。
4. **本地设置**：提供方配置状态、默认地区语言、缓存路径、质量阈值和合同权利声明。

### 7.2 工作台布局

- 顶部：任务名、任务类型、搜索状态、继续搜索、暂停、筛选和导出。
- 左侧：类别队列；每行展示标签路径、候选数、已选数、目标数、错误和缺口。
- 中间：响应式候选图片网格；卡片展示选择状态、来源、尺寸、授权状态和质量警告。
- 右侧抽屉：大图、完整标签、全部来源链、原始页面链接、查询词、检查结果、授权操作和换类操作。
- 底部固定选择栏：本次已选数量、未解决问题和进入导出入口。

支持多选、范围选择、近重复折叠、一键保留最高分辨率、移动到兄弟标签、仅看未审及隐藏已拒绝。键盘支持选择、拒绝、跳过、打开来源和切换下一张。

### 7.3 任务类型差异

- 广告品类：每个资产必须唯一归属一个叶子标签；跨类别重复进入冲突队列并阻断导出。
- 内容审核：允许多标签；敏感缩略图默认模糊，用户主动点击才显示；非法内容永不持久化或导出。

## 8. 数据模型

核心实体：

- `collection_job`：任务、任务类型、导出模式和配置快照。
- `taxonomy_node`：任务内不可变标签树快照。
- `label_target`：叶子类别的商品、条件、风格和目标数量。
- `query_run`：提供方、查询、状态、游标、配额与错误。
- `search_hit`：每次查询中的原始命中与排名。
- `asset`：下载后的实际字节、媒体属性和哈希。
- `candidate`：任务内人工审核单元，可聚合多个 search hit。
- `candidate_label`：候选的请求标签与最终分配标签。
- `quality_check`：检查器版本、结果、严重级别和测量值。
- `review_event`：选择、拒绝、换类、授权确认和警告覆盖的事件记录。
- `export_snapshot`：一次导出的固定候选集合与生成状态。

状态拆分为：

```text
pipeline_state: discovered | fetching | fetched | processed | invalid | quarantined
review_state: unreviewed | selected | rejected
export_state: not_exported | exported
```

搜索命中与实际图片资产不可合并成同一实体；同一图片由多个查询或来源发现时只展示一个候选，但完整保留全部 provenance。

## 9. 下载、质量、去重与安全

### 9.1 下载安全

- 仅允许 HTTP/HTTPS。
- 阻断 localhost、私网、保留地址和云元数据地址；DNS 解析及每次重定向后重新校验。
- 设置连接、读取、总时长、重定向数、字节数和像素数上限。
- 依据文件魔数识别真实类型，拒绝 HTML、SVG、脚本、动画、多页和伪装文件。
- 默认最大 25 MB、100 MP；小于 128 像素任一边阻断，小于 512 像素任一边软警告。
- 导出前重新解码、自动旋转、移除 EXIF 并安全重编码。

### 9.2 去重

顺序为 URL 规范化、源文件 SHA-256、归一像素 SHA-256、感知哈希。完全重复自动合并，近重复只分组不静默删除；用户可保留最高分辨率版本。去重范围是整个任务，不局限当前标签。

### 9.3 软质量检查

分辨率偏低、模糊、严重压缩、极端宽高比、文字或水印过多、商品主体过小、生活实拍倾向、标签相关度低、风格不匹配和授权未知均显示警告并影响排序。首版不依赖外部视觉模型；视觉语义项可以显示为“未自动检查”，并保留未来接入模型评分器的接口。

## 10. 授权与导出策略

### 10.1 严格合规模式

仅允许以下素材进入 ZIP：

- 回源确认的 CC0/PDM；
- 用户自有素材；
- 有明确授权证据的素材；
- 提供方合同和图片权利都允许下载与训练的素材。

授权未知、提供方只允许发现或合同权利未确认时阻断导出。

### 10.2 内部研发模式

授权未知图片可在用户逐项或批量确认后导出，确认记录进入 manifest。以下情况仍不可被确认绕过：

- 提供方合同明确禁止持久存储或训练，且用户未声明取得额外合同权利；
- 非法内容或技术安全阻断；
- 广告品类任务中的跨叶子冲突；
- 原文件缺失或哈希变化。

界面和 ZIP README 都明确说明：来源记录与用户确认不等同于取得版权许可。

## 11. ZIP 数据集格式

```text
<dataset_slug>_<export_id>/
  README.md
  dataset.json
  taxonomy.json
  manifest.jsonl
  checksums.sha256
  images/
    <label_id>__<ascii_slug>/
      <candidate_id>_<sha8>.jpg
  reports/
    acquisition_summary.json
```

- 广告品类模式每张图片只有一个叶子标签目录。
- 内容审核模式按 primary label 放置，完整多标签写入 manifest。
- 文件名不使用网页标题或原始文件名。
- `manifest.jsonl` 每行包含候选 ID、相对路径、源/导出哈希、媒体属性、标签、商品条件、来源数组、许可状态、检查结果、审核覆盖与转换记录。
- `taxonomy.json` 保存稳定 ID、父节点、名称和完整路径。
- `dataset.json` 保存应用版本、策略版本、任务类型、导出模式、总数、来源统计和许可统计。
- `checksums.sha256` 覆盖全部图片和元数据文件，但不覆盖自身。
- ZIP 不得包含密钥、Cookie、本机绝对路径或仍带认证签名的 URL。

## 13. 错误处理与恢复

错误记录包含 `error_code、scope、stage、retryable、user_message、technical_detail、attempt_count、next_retry_at`。

- 429、超时和临时 5xx 使用带抖动的指数退避。
- 401/403 凭据错误阻断对应提供方并给出设置入口。
- 单图 403/404、解码失败或质量阻断不会终止任务。
- 暂停和刷新不丢失候选或审核状态。
- 进程重启后将运行中的查询和下载重置为可重试状态。
- 导出先写临时文件，校验成功后原子重命名；失败不会留下可误认的 ZIP。
- 用户可仅重试失败来源、失败类别或失败图片。

## 14. 测试与最终验收

### 14.1 单元测试

- 标签解析、稳定 ID、查询生成、提供方结果归一化。
- 授权门禁、状态机、去重决策、ZIP 路径与 manifest 生成。
- SSRF 地址判断、MIME 校验、重试策略和错误映射。

### 14.2 集成测试

- 使用伪提供方验证多源并发、局部失败和限流。
- Fastify 注入测试覆盖任务、搜索、审核、导出 API。
- 使用本地图片 fixture 验证哈希、近重复、损坏文件和安全重编码。
- 解压导出 ZIP，校验文件数、manifest 行数、标签引用和 SHA-256。

### 14.3 浏览器验收

1. 创建广告品类任务，导入示例层级标签并生成查询。
2. 从 Openverse 或任意已配置真实提供方获得候选。
3. 按来源、授权、尺寸和审核状态筛选。
4. 选择、拒绝、查看来源、换类，刷新后状态保持。
5. 在内部研发模式确认未知授权项并生成 ZIP。
6. 验证严格模式会阻断未知授权项。
7. 创建内容审核任务，验证多标签和敏感图模糊交互。
8. 验证桌面和移动窄屏无关键内容溢出，核心键盘操作可用。

### 14.4 验收数据正确性

- 图片文件数等于 manifest 行数。
- manifest 的每个相对路径存在且恰有一条记录。
- 所有校验和通过，所有 label ID 能在 taxonomy 中解析。
- 广告品类导出不存在同一资产对应两个叶子标签。
- ZIP 不包含密钥、Cookie、绝对路径、临时签名参数或未选图片。

## 15. 实施优先级

按可用闭环而不是按技术层拆分：

1. 基础工程、数据库、共享契约与伪提供方。
2. 任务/标签创建和工作台骨架。
3. Openverse 真搜索与统一适配器注册表。
4. 候选审核、状态持久化、授权门禁与 ZIP 导出。
5. Brave、百度千帆、SerpApi、DataForSEO 适配器。
6. 下载安全、去重、错误恢复和完整测试。
7. 视觉打磨、响应式和浏览器端最终验收。

## 16. 主要风险与缓解

- **电商广告召回不足**：使用多语言查询、父级消歧、多来源聚合和可编辑查询；不承诺 Openverse 单源覆盖。
- **第三方 URL 失效或防盗链**：逐图局部失败、保存来源页、允许重试和替换；不绕过限制。
- **API 条款变化**：适配器带权利策略和能力元数据，单源可禁用而不影响系统。
- **未知版权**：双导出模式、合同权利声明、逐项来源记录和明确 README。
- **本地进程承载批量任务**：有界并发、SQLite 恢复和原子导出；规模增长后才考虑独立 Worker。
- **视觉语义过滤不准确**：首版保持人工审核为最终判断，不将查询词命中误当作真实标签。
